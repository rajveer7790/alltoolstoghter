# Document backend and open-source workspaces

This is a separate, working Python document API. Netlify serves the Next.js static frontend and the included PdfCraft WebAssembly editor; it does **not** execute these Python/Office/model services. No paid external AI API key is needed for the integrations below.

## Included and optional capabilities

- `lib/documents/tools.json` is the shared frontend/backend operation contract: 58 entries, including 12 local operations, one complete browser editor, and 45 server operations. Forty-six have individual tool pages.
- Native CPU processing: editable text/tables to DOCX, XLSX/CSV extraction, embedded images/attachments/bookmarks, password-based AES-256 encryption/decryption, annotation removal, repair, raster/grayscale/TIFF/image slides, visual comparison, OCR, qpdf linearization, Ghostscript compression and pdfcpu validation/optimization.
- Gotenberg 9.6.0: Word, Excel, PowerPoint and OpenDocument to PDF; uploaded HTML to PDF; PDF/A remediation. HTML JavaScript and network access are disabled in the supplied configuration.
- Stirling PDF: optional live OpenAPI discovery of multipart file-processing forms. The gateway never accepts a caller-supplied upstream URL/path. Key-dependent, administrative, outbound-URL and unsupported structured forms are reported as excluded rather than shown as working. Engine edition/allowance failures remain explicit failures.
- Docling, PaddleOCR, MinerU and Marker: separate optional model workers. No `--use_llm` or hosted AI mode is used. First-use public model downloads can be large. Configure separate workers and caches; do not install all model stacks in one Python environment.
- Filee and GenOffice: installed-CLI worker adapters. Their document converters are usable headlessly; the whole desktop GUI is not copied into Next.js. Format support is determined by the actual installed CLI. GenOffice cloud/AI commands are excluded.
- ONLYOFFICE Community Edition: optional one-hour editor sessions with generated internal JWT signing, bounded uploads, signed callbacks and constrained save URLs.
- BentoPDF: optional independent, unmodified self-hosted workspace. All 114 reviewed tool IDs remain in `lib/documents/bento-tools.json`. The Next.js app is not relicensed or presented as a fork of BentoPDF. AGPL/component/model obligations still apply. Paid Hyper Compress/Kura or enterprise rights are not supplied.
- PdfCraft 0.21.1: shipped separately under `/pdf-editor/` by the frontend postbuild step. Its exact release digest, notices, model attribution and licenses are retained. It needs no backend. Large OCR jobs need substantial browser memory.

The complete 15-project source report mapping is at `/open-source` and `docs/OPEN_SOURCE_DOCUMENT_COVERAGE.md`.

## Start the CPU stack

Requirements: Docker Compose v2, outbound network access during image build, and adequate disk space. The CPU API and Gotenberg should have at least 4 GB RAM together; Office and model profiles need more. Build and test against your own documents before a public rollout.

From the repository root:

```bash
python backend/documents/setup.py
# Edit backend/documents/.env: set the real API/workspace domains and CORS origin.
docker compose --env-file backend/documents/.env -f backend/documents/compose.yml up -d --build documents gotenberg web-api
curl http://127.0.0.1:8790/health
curl http://127.0.0.1:8790/capabilities
```

The service binds only to localhost on the host. `setup.py` generates a random **internal** ONLYOFFICE secret and preserves an existing `.env`. Never commit `.env` or expose internal engine ports.

For HTTPS, point the API/workspace domains at the host, set them in `.env`, then enable Caddy:

```bash
docker compose --env-file backend/documents/.env -f backend/documents/compose.yml --profile public up -d caddy
```

The default frontend calls `/api/documents`, which Netlify proxies to `https://api.alltoolstogether.com/api/documents`. Caddy strips that prefix and forwards to this service. If deploying on another domain, change that redirect and CSP, or set `NEXT_PUBLIC_DOCUMENT_API_BASE` to the correct public endpoint and rebuild. The supplied Caddy configuration forwards other API routes to the existing Express writing/URL service (`web-api`), preserving those routes. Its optional provider settings remain independent.

## Optional workspaces

```bash
# BentoPDF isolated browser workspace. Review its current source/component licenses first.
docker compose --env-file backend/documents/.env -f backend/documents/compose.yml --profile bento --profile public up -d bento caddy
# ONLYOFFICE editor. Uses the internal secret generated by setup.py, not a third-party API key.
docker compose --env-file backend/documents/.env -f backend/documents/compose.yml --profile office --profile public up -d onlyoffice caddy
# Stirling: set STIRLING_URL=http://stirling:8080 in .env, then recreate documents too.
docker compose --env-file backend/documents/.env -f backend/documents/compose.yml --profile stirling up -d stirling documents
```

Capabilities return workspace links only when the corresponding internal service responds. Keep disabled profiles' URLs blank. Community/edition restrictions are not bypassed. Stirling login is disabled only on the isolated private Docker network; its API is never directly published. The gateway exposes reviewed file forms, not its admin surface.

Pin optional image digests after validating your deployment. `latest` is used only for upstream workspaces where deployment-specific version selection is necessary; do not silently update them in production.

## Optional model workers

Set only the engine URL you enable (for example `DOCLING_URL=http://docling:8790`), then start that profile and recreate documents:

```bash
docker compose --env-file backend/documents/.env -f backend/documents/compose.yml --profile docling up -d --build docling documents
```

Other profiles are `paddle`, `mineru`, `marker`. For MinerU and Marker, review current **code and model-weight** terms and set the corresponding `*_LICENSE_ACCEPTED=true` only when eligible. The values are false by default. Attribution appears on the tools and source page. No commercial eligibility is assumed.

Model caches are persistent volumes and may need UID 10001 ownership depending on the volume driver. Reserve several GB of RAM/disk per worker. CPU speed varies; no conversion benchmark or Adobe-equivalent fidelity is claimed. PaddleOCR may produce separate DOCX files per page, returned as a ZIP.

## Installed Filee / GenOffice workers

On a separate supported machine, install the official Filee or GenOffice release and verify `filee --version` or `genoffice --version`. Install this API's Python requirements, leave all `*_URL` variables blank **on that worker** to avoid proxy loops, then run:

```bash
python -m pip install -r backend/documents/requirements.txt
uvicorn backend.documents.app:app --host 127.0.0.1 --port 8790 --no-access-log
```

Use a private reachable worker address in the gateway's `FILEE_URL` / `GENOFFICE_URL`. Do not publish an unauthenticated worker on the internet. The adapter invokes only `convert` with validated output extensions and controlled input/output paths, not arbitrary CLI commands. Optional Filee engines and bundled libraries keep their own licenses. These installed-CLI paths require runtime verification on the machine where those products are installed.

## Request contract

`GET /health`, `GET /capabilities`, `POST /process/{id}`. The public proxy adds `/api/documents` before these paths. Normal tool uploads use repeated multipart `files`; `options` is a JSON object. Discovered Stirling tools use the named upload slots returned in capabilities. Only declared options are accepted.

Limits: eight files; 20 MB per file; 32 MB request; 64 MB result; 200 PDF pages on the server; two concurrent jobs by default. Rate limit: 12 requests/minute per connection IP. When reverse-proxied, this is an aggregate limit unless trusted client-IP handling is configured by the operator; arbitrary forwarded headers are not trusted. Native processing runs in a killable process with CPU/address-space limits; subprocesses never use a shell. Converted files are deleted after the response. Office files persist for at most one hour and the minute-based janitor removes expired sessions. Backups/log retention remain operator responsibilities.

Keep container memory/CPU/tmpfs limits. Run as nonroot and keep the API behind an HTTPS gateway with appropriate public rate limiting. Uploaded documents are untrusted; no parser provides a guarantee against all malformed files.

## Tests and indexing

```bash
python -m unittest discover -s backend/documents/tests -v
npm run check
npm run build
npm run audit:export
```

`.github/workflows/document-engines.yml` builds the real CPU container and smoke-tests native conversions, qpdf, OCR, pdfcpu and Gotenberg. Model adapters have request/transport tests; large optional model/desktop stacks require separate deployment tests and are not claimed as benchmarked.

Server-only SEO pages remain `noindex` and outside the sitemap until `NEXT_PUBLIC_DOCUMENTS_READY=true` is explicitly set **after** the required services are working. They remain reachable from Document Studio with honest availability messages. Local operations and the browser editor are indexable immediately. Health checks never turn an unavailable tool into a fake successful conversion.

Before enabling server-page indexing, run `python backend/documents/check_ready.py https://api.alltoolstogether.com/api/documents`. It must report all required pages ready. Only then set `NEXT_PUBLIC_DOCUMENTS_READY=true` for the frontend and rebuild. Optional model/workspace tools are not included in that index-readiness requirement.

## November 2026 fidelity upgrade

PDF-to-Word defaults to DocVortex 0.6.24 native structure recovery. The UI offers three explicit modes: editable document, basic text/tables, or page images with no editable text. Basic mode no longer duplicates table cells in prose, and page-image mode anchors each image to the original page dimensions. Optional local OCR handles scans; it is never a hosted API. Complex pagination, fonts, equations and OCR still require review. This is not a claim of lossless editable conversion.

PDF-to-HTML now returns a ZIP containing semantic HTML and all relative image assets. Unzip before opening it. Word/Office-to-PDF uses the custom Gotenberg 9.6.0 image with Noto/CJK and metric-compatible open fonts, lossless image export, original image resolution and flattened form fields by default. Interactive fields can be retained explicitly. Custom licensed fonts must be supplied by the operator when required; arbitrary font uploads or outbound linked-image downloads are not enabled.

Rebuild **both** `documents` and `gotenberg` when upgrading; a frontend redeploy alone cannot apply these backend changes. `Dockerfile.gotenberg` builds the font image on AMD64 and ARM64. MinerU's adapter now uses the 4.2.3 local `mineru-kit` ZIP contract; the old `-p/-o/-b` CLI is not used. Optional PaddleOCR 3.7.0 and Marker 2.2.0 are pinned. Their heavyweight model stacks still need deployment-specific inference verification; the native DocVortex path and local OCR/Office stack are tested separately.

An optional `geometric` profile exposes `PDF to Word — Geometric Layout` as a separate choice. It uses the previously measured pdf2docx/PyMuPDF path and is disabled by default. Review the dependency's AGPL/commercial conditions and source-offer obligations before public deployment; set `GEOMETRIC_LICENSE_ACCEPTED=true` on that worker and `GEOMETRIC_URL=http://geometric:8790` on the gateway only after review. No external API key is required. Its reconstruction is not lossless and the upstream wrapper is no longer actively maintained. Scans need OCR first.
